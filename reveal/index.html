Configuration

Portail développeur · société Intacct

Configuration · Portail développeur

  1. Ouvrir developer.sage.com/intacct et cliquer sur View Console.
  2. Se connecter avec un Sage ID, créer une organisation, puis s'inscrire au programme Sage Intacct REST API (Sender ID requis).
  3. Créer une application et noter le Client ID et le Client Secret.
  4. Renseigner les Redirect URIs, le scope, et le mot de passe Sender ID (Web Services License Password).

2

Authentification

OAuth 2.0 · Client Credentials & Authorization Code

Authentification · Client Credentials

Ce flux sert aux accès machine à machine, sans interaction utilisateur.

Obtenir un jeton

Envoyer une requête POST vers oauth2/token avec un corps form-urlencoded.

  1. Renseigner grant_type avec la valeur client_credentials.
  2. Ajouter le client_id et le client_secret de l'application.
  3. Indiquer username au format webservice@company ou webservice@company|entity.

À retenir : l'ID client doit être lié à un utilisateur Web Services (voir ch. 1). La réponse contient un access_token et un refresh_token, valides environ 6 heures.

Note : le suffixe |entity est optionnel. Vous choisissez le périmètre du jeton à la demande : top level ou entité uniquement.

© The Sage Group plc, or its licensors. All rights reserved.

Authentification · Client Credentials · Exemple

Dans Postman, exécuter la requête Get Token (Client Credentials).

POST /oauth2/token

Corps

{
  "grant_type": "client_credentials",
  "client_id": "xxx.app.sage.com",
  "client_secret": "••••••",
  "username": "webservice@company|entity"
}

200 OK

Réponse

{
  "access_token": "eyJ...",
  "refresh_token": "eyJ...",
  "token_type": "Bearer",
  "expires_in": 21600
}

Note : omettez |entity dans username pour obtenir un jeton au niveau top level.

Authentification · Authorization Code

Ce flux sert lorsqu'un utilisateur réel se connecte via votre application (navigateur, mobile). Les appels API sont exécutés à son nom, et non via un compte Web Services.

Flux en 2 étapes

  1. Dans le navigateur, rediriger l'utilisateur vers GET oauth2/authorize avec les paramètres requis en query string. Sage Intacct renvoie un code d'autorisation.
  2. Côté serveur, échanger ce code via POST oauth2/token (corps form-urlencoded) pour récupérer les jetons.

À retenir : le code est à usage unique. La Redirect URI doit correspondre à celle déclarée dans le portail. Le client_secret ne doit jamais transiter côté navigateur.

Note : il n'y a pas de suffixe |entity dans ce flux. Le jeton est émis au niveau top level, ou sur l'entité par défaut de l'utilisateur si elle est définie dans Intacct.

© The Sage Group plc, or its licensors. All rights reserved.

Authentification · Authorization Code · Exemple · Étape 1

Étape navigateur : construire l'URL d'autorisation avec les paramètres en query string.

GET /oauth2/authorize

Paramètres URL

?response_type=code
&client_id=xxx.app.sage.com
&redirect_uri=https://app.example/callback
&scope=offline_access

302 Redirect

Réponse · callback

https://app.example/callback
  ?code=AUTH_CODE_HERE

© The Sage Group plc, or its licensors. All rights reserved.

Authentification · Authorization Code · Exemple · Étape 2

Étape serveur : dans Postman, exécuter Get Token (Authorization Code) avec un corps form-urlencoded.

POST /oauth2/token

Corps

{
  "grant_type": "authorization_code",
  "client_id": "xxx.app.sage.com",
  "client_secret": "••••••",
  "code": "AUTH_CODE_HERE",
  "redirect_uri": "https://app.example/callback"
}

200 OK

Réponse

{
  "access_token": "eyJ...",
  "refresh_token": "eyJ...",
  "token_type": "Bearer",
  "expires_in": 21600
}

Démo : voir la branche lesson-auth-code-worker (Worker Cloudflare).

Authentification · Top level et entité

Dans une société multi-entités, le jeton fixe un contexte d'accès. Selon le flux utilisé, deux approches permettent de cibler les enregistrements d'une sous-entité.

Cibler une sous-entité

  1. Conserver un jeton top level et ajouter le header X-IA-API-Param-Entity à chaque requête API, avec l'ID entité (propriété company-config/entity.id, ex. CentralUS-35).
  2. Ou obtenir un jeton limité à l'entité dès le départ : suffixe |entity dans username (Client Credentials), ou paramètre location_id lors d'un POST oauth2/token avec grant_type=refresh_token.

À retenir : avec Client Credentials, vous choisissez le périmètre à l'émission du jeton. Avec Authorization Code, le jeton est top level ou entité par défaut de l'utilisateur — le header permet ensuite de cibler une autre entité si le jeton est top level.

© The Sage Group plc, or its licensors. All rights reserved.

Authentification · Top level et entité · Exemple

Jeton top level · cibler une entité par header ou par refresh.

GET /objects/vendor

Header · requête API

Authorization: Bearer <top_level_token>
X-IA-API-Param-Entity: CentralUS-35

POST /oauth2/token

Corps · refresh vers jeton entité

{
  "grant_type": "refresh_token",
  "client_id": "xxx.app.sage.com",
  "client_secret": "••••••",
  "refresh_token": "eyJ...",
  "location_id": "CentralUS-35"
}

Note : le refresh avec location_id renvoie un nouveau jeton utilisable pour les appels suivants, sans header entité à chaque requête.

Model · Query · Export

Lecture des données · Model

Le service Model retourne les champs et les relations d'un objet, d'un service ou d'une autre ressource — à consulter avant de construire une Query.

Requêtes types

Tous les appels sont des GET vers /services/core/model, avec le header Authorization: Bearer.

  1. /services/core/model — définition courte de toutes les ressources de la version courante.
  2. ?name=company-config/department — modèle complet d'une ressource précise (<application>/<ressource>).
  3. ?name=projects/task&version=v1 — modèle complet pour une version d'API donnée.
  4. ?version=v1&schema=true&type=workflow — modèle complet de toutes les ressources d'un type (object, service ou workflow) pour une version.

À retenir : name identifie une ressource (objets custom : platform-apps/nsp::<nom>). schema=true renvoie le modèle complet ; par défaut, il est false pour une liste et true pour une ressource unique.

© The Sage Group plc, or its licensors. All rights reserved.

Lecture des données · Model · Exemple

Postman · modèle du département company-config/department.

GET /services/core/model

Paramètres URL

?name=company-config/department

200 OK

Réponse · extrait

{
  "ia::result": {
    "fields": {
      "id": { "type": "string", "nullable": false },
      "key": { "type": "string", "readOnly": true },
      "name": { "type": "string", "mutable": true },
      "status": { "type": "string", "mutable": true }
    }
  }
}

Note : chaque champ indique type, nullabilité, mutabilité, etc. — utile pour choisir les fields et relations d'une Query.
